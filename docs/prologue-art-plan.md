# 四幕前置劇情背景美術與實作單

目標：每幕一張獨立插畫，與 `assets/guardian-archive-hero.webp` 的修復室世界一致。原劇情文字、順序、按鈕、鍵盤焦點與導覽事件不變。先前設計文件的「序章可重用主視覺、不逐幕生成」由本次使用者明確要求覆蓋。

## 共同美術規格

- 參考首頁圖的手繪童書／冒險故事書筆觸：細緻紙張、木桌與文物材質，深海藍與青綠陰影、琥珀燈光、少量燈塔金航線。畫面有敘事焦點，避免照片感、扁平向量與制式奇幻遊戲卡面。
- 四張皆為無文字、無數字、無水印、無 UI 的橫幅插畫；不要讓 AI 在圖上畫可辨識的歷史說明或八個序號。危機感適合國小高年級，不做恐怖臉、武器、血腥或文化符號拼貼。
- **構圖各幕不同**：第一幕左文字／右景物，第二幕右文字／左黑霧，第三幕上方偏左文字／右下檔檔，第四幕下方文字／上方航線。各自的文字安全區約占畫面 50–60%，以低細節暗木或深海藍構成，主體邊緣預留至少 10% 裁切餘量。圖片不承載任何必讀資訊；正文始終以 HTML 呈現。
- 每張輸出目標 1536×1024 px；若內建工具無法指定，取最接近的橫幅輸出。最後轉成同尺寸或更小的 WebP，品質以肉眼無明顯筆觸劣化為準，單張目標 ≤ 350 KB（複雜場景可放寬至 500 KB）。檔名固定如下，放在 `assets/`；不替換首頁圖。

| 幕 | 檔名 | 情節與畫面 brief |
|---|---|---|
| 1 半夜的怪事／故事正在消失 | `prologue-01-museum-night.webp` | **右景／左文**。海圖修復室午夜遠景：右半暖燈照修復桌，後方八座展櫃的燈逐一黯淡；古海圖金色航線被墨藍薄霧抹去，地形模型與季風曆失序。左側 55% 為安靜暗牆與輕微紙紋，供文字；神秘而非驚悚。 |
| 2 抹除者出現／牠只想留下一個答案 | `prologue-02-erasure.webp` | **左景／右文**。延續修復室，但鏡頭轉向左側展櫃：無臉黑霧在畫面左半凝成剪影，像橡皮擦般讓多條發光航線只剩一條；文物光點沿霧散開。右側 55% 是低細節深海藍木牆，供文字；冷藍霧與琥珀燈對照，不畫駭人面孔。 |
| 3 守護局求救／檔檔找到了你 | `prologue-03-dangdang.webp` | **右下景／上方偏左文**。實際成圖中，小巧舊紙文物展籤「檔檔」在右下飛起，金光照亮文物碎片與羅盤；上方偏左是低細節的深海藍留白，供文字。維持可愛而非表情包的閱讀感；標籤上沒有必讀文字。 |
| 4 任務開始／讓八件文物重新發光 | `prologue-04-eight-relics.webp` | **上景／下文**。俯瞰修復室木桌：畫面上半的破損古海圖展開，臺灣島形與八處光點由西南港口沿弧形航線連到遠端明亮展廳；少量瓷片、石器、紙籤作邊角點綴。下半約 55% 漸入深海藍暗木桌面、低細節，供文字。八光點不標號；讓橫向路線成為全幕視覺收束。 |

生成時將 `guardian-archive-hero.webp` 作為**風格與場景連續性參考**，逐幕生成，不要求直接修改首頁圖。四張完成後目視確認同一修復室、用色、筆觸、光源方向與檔檔造型能連成一組，並檢查圖中文字與視覺瑕疵。

## 交給 Luna(Max) 的最小實作

1. 先讀目前 `歷史文物守護行動完整版.html` 與 `git diff`，保留既有未提交修改。只改這份 HTML 的序章標記及必要 CSS；引用四張 `assets/prologue-0*.webp`，依 `prologueScenes` 索引對應，不更動 `body`、`phase`、`title`、按鈕文案或 `showPrologue` 的事件。
2. 桌機依幕切換圖片與文字的位置：1 左文右景、2 右文左景、3 上方偏左文右下景、4 上景下文。文字區使用**實色或高不透明底**，避免直接壓在高細節插畫上。手機統一圖片在故事標題附近的上方橫幅、正文與「上一幕／下一幕／跳到玩法說明」自然垂直流，無固定高度造成裁字。保留 `data-symbol` 時避免 emoji 疊住新圖，必要時僅對有圖序章隱藏裝飾符號。圖片作純裝飾，維持語意內容在 HTML。
3. 使用既有 `cover`、漸層與媒體查詢即可，不加依賴或額外 JS 載圖機制；四幕共用同一套版型。顧及 `body.large`、375px、768px、桌機及 200% 縮放。若圖尚未到位，先完成樣式與引用，交付前檢查四個檔案均存在。

## 6 Sol 回歸驗收

- 靜態核對四幕對應四個實際可讀 WebP；每張尺寸、檔案大小、無文字雜訊，檔名與引用一致；差異僅限序章呈現及四張新圖。
- 比對改前改後四幕原文、順序、`storyPrev`、`storyNext`、`storySkip`、`backStory`、`showHowToPlay`、`showTitle`、存檔鍵與遊戲資料；語法／既有 `selfCheck()` 通過，首次進入與從玩法、地圖重看序章路徑仍通。
- 若有獲准的真實預覽，在 375×812、768×1024、1440×900 與 200% 縮放逐幕檢查四種構圖是否真有區別、主體裁切、文字對比、溢出、焦點與按鈕可達性；特別檢查較長的第 2–4 幕及放大文字。若瀏覽器仍拒絕 `file://` 且無已獲准預覽，明確標記「實際視覺驗收未完成」，不可用靜態檢查冒充。
