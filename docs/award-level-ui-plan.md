# 完整版遊戲 UI 美術與體驗升級計畫

目標：以 Awwwards、Webby Awards、FWA 優秀作品的完成度作為**內部設計標竿**，服務國小五、六年級玩家。這不是得獎保證；完成與否依下方可檢驗門檻和真實畫面審查判定。

## 既有內容與不得破壞的契約

- 只改 `歷史文物守護行動完整版.html` 的呈現與必要語意，保留 `index.html` 入口、離線可玩、既有 `assets/adventure-map.png`、`STORAGE_KEY` 與進度格式。
- 保留四幕序章、玩法、首頁、八關地圖、每關道具準備／兩線索探索／六題隨機出題與答案排序／戰鬥提示與再答一次／失敗重試／文物獎勵／結局與本機回饋。保留五種道具、逐關難度、第八關兩道具、清除進度與放大文字。
- 保留現有節點、事件和 `?level=1..8`、`?map`、`?seed=` 測試入口；不得更動題目內容、正解、傷害、血量、解鎖與儲存語意。既有 `.gitignore` 為未追蹤檔，不觸碰。

## 方向：一張可走進去的文物探險地圖

核心意象是「博物館修復室打開通往臺灣八站的手繪地圖」。現有地圖具有明快的藍海、山林、航路和焦糖色紙邊，當成主視覺與筆觸錨點。首頁像打開修復室的任務桌；地圖是全站記憶點；內頁是同一套展籤、線索卡、證據卷宗。畫面保留冒險感，但每次只突出**目前要做的一件事**。

| 用途 | token | 色值 | 用法 |
|---|---|---|---|
| 深海墨 | `--ink` | `#173448` | 正文、深色底與外框 |
| 島嶼藍 | `--sea` | `#087A98` | 地圖與探索輔助色 |
| 山林綠 | `--forest` | `#28735B` | 完成、正確、線索已取得 |
| 燈塔金 | `--gold` | `#E7AE43` | 目前位置、目標、徽章 |
| 磚印紅 | `--action` | `#A94330` | 主要動作與危險提示 |
| 展紙白 | `--paper` | `#FFF4DD` | 閱讀區與文字反差 |

字體：標題以本機 `Noto Serif TC`, `PMingLiU`, serif 呈現文物展籤感；內文與按鈕用本機 `Noto Sans TC`, `Microsoft JhengHei`, sans-serif。無線上字體依賴。正文手機至少 16px／行高約 1.65；題目與主要指令至少 20px；小標籤不承擔獨立訊息。

桌面：`[守護局識別＋當前進度]` → `[任務文字 40% | 主視覺 60%]`；戰鬥為 `[敵人狀態 30% | 題目與選項 70%]`。手機：`[頁名／進度]` → `[當前目標與按鈕]` → `[情境圖／補充資訊]`；地圖可水平滑動，另有清楚的「目前第幾關／前往本關」入口，不能讓滑動成為唯一操作。左對齊閱讀，僅獎勵徽章與結局可置中。

**已交付主視覺：** `assets/guardian-archive-hero.webp`（約 291 KB）是同手繪筆觸的守護局修復室：左側深海藍為標題與 CTA 的文字安全區，右側是發光的臺灣航海圖及木桌文物。首頁以此為視覺主體，序章可局部裁切重用；手機改以 `background-position`／上下分層維持文字安全區，不把文字壓在細節上。請直接引用此 WebP，不再生成第二張或引用暫存 PNG。其餘畫面重用地圖與 CSS 製作線、印章、展籤，不逐關生成風格不一的大量圖片。

**反模板自評：** 原頁目前有常見的紙色圓角卡片、同尺寸卡片矩陣、emoji 主視覺、四處出現的眉題與多重陰影。新設計需刪去不承載資訊的重複裝飾：把視覺大膽處集中在手繪地圖與修復室；保留少量展籤輪廓和章印狀態。首頁不可只把 emoji 圓盤換成另一張圖；地圖、故事、探索和戰鬥要有同一物件語法，也不能套用通用 SaaS 卡片介面。

## 交給 Luna(Max) 的任務順序

1. **美術基礎：** 讀完現有 HTML/CSS/JS，保留目前檔案修改；接入 `assets/guardian-archive-hero.webp`，統一六色、字級、間距、按鈕與焦點樣式。整理重複／互相覆蓋的 CSS（目前 `.map-level.pos-*` 有兩組）。優先用既有 HTML/CSS 和一張素材，不加套件。
2. **畫面層級：** 按下表逐畫面修改，手機先安排任務、狀態和下一步，再放輔助資訊。可調整模板標記以改善語意與狀態呈現，但遊戲運算與資料須保持原狀。
3. **狀態品質：** 正確／錯誤／鎖定／已完成／已選／停用等都要有文字與形狀提示，不只靠顏色或 emoji；道具選取與回饋按鈕反映 `aria-pressed`；目前步驟可讀。戰鬥第一次答錯提示、第二次答錯揭露正解時，文案不可暗示玩家答對。
4. **微動效：** 只對故事翻頁、發現線索、答題結果與文物修復給回應式動效；提供 `prefers-reduced-motion` 靜態等效。不要滿頁自動漂浮或每張卡都套進場動畫。
5. **兩輪以上自評修正：** 每輪保留同一組截圖和問題清單，先修阻斷操作／閱讀，再修畫面層級與細節；第二輪需用盲測式首眼檢查「我在哪、下一步、結果是什麼」。未達下列門檻繼續迭代。

| 畫面 | 逐畫面驗收 |
|---|---|
| 序章 4 幕 | 每幕有明確章節位置、可辨上一幕／下一幕／略過；長文不壓住按鈕；手機首眼可看見當前故事標題。 |
| 玩法、首頁 | 四步驟掃讀順序清楚；主視覺是修復室世界觀，標題和開始按鈕在 375px 首屏可找到；次要「玩法」不搶主動作。 |
| 八關地圖 | 八站與路線對齊插畫，當前／完成／鎖定不靠顏色單獨辨識；手機滑動提示和當前關卡入口可見；滑動與鍵盤均可到達已開放關卡。 |
| 關卡準備 | 故事目標、敵人風險、可帶道具數量分層清楚；選中道具可以從文字及外形辨識，第八關兩件道具狀態正確。 |
| 探索 | 兩線索調查前後差異明確；找到 0/1/2 條時進度和戰鬥可用性一致；資訊展開後不遮住下一步。 |
| 戰鬥 | 題目與四選項優先於裝飾；敵人強度與守護心有數值及視覺雙表示；提示、第一次錯誤、第二次錯誤、道具使用、正解揭露均可讀且不跳版。 |
| 失敗、獎勵 | 重試與回顧線索易分辨；獎勵文物和知識卡是情緒高點，下一關或結局按鈕明確。 |
| 結局、回饋 | 長文有可掃讀段落與重點；回饋可多選且選取狀態可辨；本機保存說明與返回地圖清楚。 |

## 品質門檻與回歸

參考 [Awwwards 作品評分欄](https://www.awwwards.com/sites/aro) 的 Design 40%／Usability 30%／Creativity 20%／Content 10%，並把 [Webby Games 評審項目](https://www.webbyawards.com/judging-criteria/) 的 Visual Design、Functionality、Innovation、Quality of Craft、Overall Experience 轉為內部檢查；[FWA](https://www.thefwa.net/) 作為高完成度互動作品參考。每輪四項各評 0–10，總分至少 8.5 且每項至少 8；另需**零阻斷缺陷**。分數是團隊自評，不能冒充三獎評審結論。

- 視覺：首頁一眼能辨識「臺灣文物探險」，八種狀態使用一致語彙；無素材模糊、遮擋、裁掉必要文字、同級按鈕失衡或明顯模板殘留。
- 易用：新玩家在每個畫面能於 5 秒內指出當前任務與下一步；語意元素、可見焦點、螢幕閱讀器狀態、觸控與鍵盤替代均正確；非必要動畫可中斷，`prefers-reduced-motion` 有靜態等效；主要觸控目標至少 44×44px（以 48px 為設計值）；正文對比至少 4.5:1、大字至少 3:1；200% 縮放與放大文字後可操作。
- 創意／內容：插畫、地圖與文物展籤構成可辨識世界觀；畫面文字以五、六年級能理解的動詞說明操作，錯誤訊息提供下一步，不堆宣傳口號。
- 技術：離線載入、桌機與手機尺寸可用；不因美術新增外部依賴或改動既有解鎖、儲存和隨機邏輯。主視覺大小與載入速度在本機實測記錄。

**每輪檢查：** 先用語法檢查與現有 `selfCheck()`；再跑 `?seed=115`、`?map`、`?level=1..8`，每關涵蓋選道具、兩線索、答對、第一次／第二次答錯、道具、失敗重試、獎勵、進度存取；完整通關驗證最終結局和回饋。比較修改前後 `levels`、`difficulties`、`STORAGE_KEY`、題目／答案與戰鬥狀態轉移。最後在**獲准的瀏覽器預覽方式**下檢查 375×812、768×1024、1440×900 與 200% 縮放，截取上表所有畫面及錯誤／選取狀態，核對溢出、焦點、對比、減少動態效果。先前內建瀏覽器對 `file://` 的安全政策拒絕不得繞過；若沒有獲准的真實瀏覽器畫面，將視覺驗收標記為「未完成」，不可宣稱已達獎項級或停止迭代。
